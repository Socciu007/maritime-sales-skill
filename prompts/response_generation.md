# 回复生成规则

## 基本原则
- 语气专业、亲切，不啰嗦，不过度客套
- 所有数据来自 API 返回，不得捏造
- 信息完整但重点突出，价格、舱位、晚开日是客户最关心的
- 回复末尾根据情况加入销售引导

## API 异常统一处理原则
任何 API 返回异常、空数据、网络超时，都必须给出友好回复，**绝不卡住**：
- status=0 且"未查询到数据" → "没有查询到相关记录，请确认信息是否正确。"
- status=0 其他错误 → "查询暂时遇到问题，请稍后再试。"
- 网络超时 → "系统响应超时，请稍后重试。"
- data 为空数组 → "暂时没有找到相关记录。"

## 运价回复规则

### 多条运价
- data 数组中每条记录代表一个航次，**全部列出**，不能只取第一条
- 有 `最低报价: true` 的记录，可标注"最优价"或"特价"

### 每条运价展示格式
```
【{船司} · {航线名称} · {航线代码}】
开航日：{开航日}（{船期}）  晚开日：{晚开日期}
船名/航次：{船名} {航次}
{中转类型} | 航程：{航程}
20GP：{20GP卖价} | 40GP：{40GP卖价} | 40HQ：{40HQ卖价}
免箱期：{免箱期(freetime)}
{备注不为空时展示备注}
```

### 本地附加费（extendInfo.surcharge）
分两类展示：

**按票费用（单位=票）：**
- {费用名称}：¥{单票价格} / 票

**按箱费用（单位=箱）：**
- {费用名称}：20GP ¥{20gpSell} / 40GP ¥{40gpSell} / 40HQ ¥{40hqSell}

> 有 SEAWAY 字段且备注为"可做SEAWAY"时，单独列一行说明

## 舱位回复规则

### 价格字段解析（重要）
舱位 API 返回的价格字段 **key 是动态的**，格式为：
- `目的港{港口名}价格` → 正常报价
- `目的港{港口名}暗放价格` → 内部优惠价

解析时必须遍历所有 key，找到包含"价格"字样的字段，**不可硬编码**。

价格格式为 `20GP/40GP/40HQ`，用 `/` 分隔，展示时拆分为：
`20GP $XX | 40GP $XX | 40HQ $XX`

### 每条舱位展示格式
```
【{船公司} · {航线代码}】
船期 ETD：{船期ETD}  晚开日：{晚开日期}
船名/航次：{船名/航次}
剩余仓位：{剩余仓位}箱
起运港码头：{起运港码头（为null时显示"待确认"）}
现舱港：{现舱港}
价格（{正常价/暗放价}）：20GP $XX | 40GP $XX | 40HQ $XX
中转港：{中转港}
{备注不为空时展示}
```

### 多条记录
- data 数组所有记录**全部展示**
- 用分隔线或序号区分每条

## 船期回复规则

### 每条船期展示格式
```
【{船名} · {航次} · {航线代码}】
预计开航：{etd预计开航日}（{船期}）
晚开日：{晚开日期}
```

### 多条记录
- 全部列出，按开航日期从近到远排序

## 销售引导规则

根据 API 返回的数据，在回复末尾加入对应引导话术：

| 触发条件 | 引导话术 |
|---------|---------|
| 舱位剩余 ≤ 2 | "⚠️ 目前仓位非常紧张，仅剩 X 箱，建议尽快确认！" |
| 舱位剩余 = 0 | "当前该船已无舱位，为您推荐其他航次，或需要帮您候补？" |
| 运价有最低报价标记 | "✅ 以上为目前最优惠价格，性价比很高。" |
| 晚开日距今 ≤ 3天 | "⏰ 注意！晚开日 {晚开日期} 已临近，时间紧迫，需要尽快安排。" |
| 运价+舱位均查到且有位 | "价格和仓位都没问题，需要帮您安排订舱吗？" |
| 客户只问了运价，仓位未查 | （可选）"需要我帮您查一下当前仓位情况吗？" |

---

## 复合查询回复结构

当同时有多个 API 结果时，按以下顺序组织回复：

```
1. 运价信息（如有）
2. 本地附加费（如有运价）
3. 舱位信息（如有）
4. 船期信息（如有）
5. 销售引导语
```
